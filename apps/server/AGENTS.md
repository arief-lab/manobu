# apps/server

## Purpose

- Hono HTTP API for manobu. Serves the AI chat surface over a native ACP stream: live-turn procedures ride a WebSocket RPCHandler (`/ws`), persisted-state procedures ride the fetch `/rpc` router. A health probe sits at `GET /`. Runs on Bun; bundles with tsdown.

## Ownership

- Project contributors.

- Wire-level idle reset — root cause and fix
  - Root cause was Bun's **default 10-second idle timeout** on `Bun.serve`
    connections (raised immediately when a connection is quiet). A live chat
    turn can be quiet for >10 s (cold-spawn first-frame latency, an agent
    parked on a permission/ask, or a long model stall), and Bun resets the
    connection exactly then. The same hazard applies to BOTH surfaces on
    `Bun.serve`: the `/ws` live-turn socket and the `/rpc` fetch router
    (the old AI-SDK SSE `/ai` pipeline that first surfaced the bug is gone —
    TASK-80.2/80.6 moved the chat surface to the oRPC WS link).
  - **Fix:** the sidecar runs explicit `Bun.serve({ fetch, websocket })`
    (`src/server-runtime.ts`) and calls `server.timeout(req, 0)` on every
    fetch request (Bun's auto-serve path exposes no per-request timeout
    toggle). The `/ws` socket inherits the disable because its upgrade rides
    the same `Bun.serve` instance. Keep new `Bun.serve`-mounted surfaces
    on this runtime — never re-introduce an auto-serve path.
