# Real JLPT paper anatomy: per-level 大問 blocks, formats and pinned official sources

> **Status:** reference / specification
> **Date:** 2026-09-29 (research re-run same day; the composition page, all five per-level PDFs and the official 問題構成例 sheet were fetched and read)
> **Purpose:** the single offline ground truth for the TASK-173 *real-mode* content tasks, so a worker does not re-research the exam and can pin a test against a named source.
> **Serves:** TASK-173.4 (block order/counts), 173.5 (文脈規定), 173.6 (文の組み立て), 173.7 (読解 N5/N4), 173.8 (聴解), 173.9 (N3/N2/N1 formats).
> **Related docs:** doc-4 (high-level JLPT landscape, timings, eligibility), doc-14 (our request→assemble→validate pipeline), doc-16 (item engine), doc-21 (corpus supply), doc-25 (QA findings D5/D6). This doc owns the *official paper anatomy* that doc-4 only names at section level.

## 0. Sourcing honesty (read first)

Three kinds of statement appear below, and the difference matters because the whole point of TASK-173.1 is *refuse, do not fabricate*:

- **CONFIRMED** — quoted from a **current** official jlpt.jp document, read directly (Section 1). Block order, 大問 numbering, block names, ねらい and section times are all in this class now.
- **CONFIRMED-STALE** — the per-block 小問数. The **only** count table the Foundation has ever published online is the 2009 問題構成例 sheet (and the same numbers in the 2010 guidebook, where the footnote calls them 目安 "indicative"). Its own section times disagree with the current paper for N5, N4 and N1 聴解, so its counts describe a paper that no longer exists.
- **NOT PUBLISHED** — the current per-block 小問数. The 2020 and 2022 time reforms changed the sections they shortened, and no current official document states the resulting per-block counts anywhere. The composition page publishes only a per-level ○/― presence matrix.

Consequence for TASK-173.4: a count written into `packages/item-engine/src/paper.ts` can be **labelled indicative with its 2009 source cited**, or it can be omitted, but it cannot be presented as the official current count, because that number is not public. Writing a guessed count into a blueprint is the same fabrication the real mode exists to refuse.

## 1. Pinned official sources (all read 2026-09-29)

`WebFetch` was rate-limited (API code 115, reset ≈ 2026-10-21); `curl` + `pdftotext -layout -enc UTF-8` works and is how everything below was read. Re-run those two commands, do not reach for WebFetch.

- 試験科目と問題の構成 (the "official composition page" the ACs name): `https://www.jlpt.jp/guideline/testsections.html` · English `https://www.jlpt.jp/e/guideline/testsections.html`. Carries: section split + times, and the 大問 × level ○/― presence matrix. **Carries no counts.**
- レベル別 大問のねらい (current, one PDF per level; gives 大問 number, name, ねらい and section time):
  - N1 `https://www.jlpt.jp/guideline/pdf/n1_revised.pdf`
  - N2 `https://www.jlpt.jp/guideline/pdf/n2.pdf`
  - N3 `https://www.jlpt.jp/guideline/pdf/n3.pdf`
  - N4 `https://www.jlpt.jp/guideline/pdf/n4_revised.pdf`
  - N5 `https://www.jlpt.jp/guideline/pdf/n5_revised.pdf`
- 問題構成例 (the only per-block 小問数 table; image-only PDF, one page per level, **2009-08-04** internal date, no text layer): `https://www.jlpt.jp/samples/pdf/sample_kousei.pdf` — read it with `pdftoppm -r 150 -f <page> -l <page> -png` and look at the render; N1=2, N2=3, N3=4, N4=5, N5=6. Its own footnote: 「小問数」は毎回の試験で出題される目安で、実際の試験での出題数は多少異なる場合があります。また、小問数は変更される場合があります。
- 公式サンプル問題 (full papers, newest set is **2018**, i.e. also pre-reform for N4/N5): `https://www.jlpt.jp/samples/sampleindex.html` → `sample2018/pdf/N{1..5}{V,G,R,L}.pdf`. The text layer uses a broken number encoding and the 大問 headings are kana, so these are usable for item *shape*, not for counting.
- Overall guidebook (same 目安 counts, pre-2020 times): `https://www.jlpt.jp/reference/pdf/guidebook1e.pdf`
- 文の組み立て format source (TASK-173.6): the guidebook's pp.43-44 carry the worked 文の文法2（文の組み立て）format — five 小問, each a sentence split into four fragments with one slot marked ★ and the four offered scrambled as the options. Its rule ② is the constraint the mask enforces: a sentence-ending `。` may never sit inside the blank, so a fragment that closes the sentence cannot be parked in a non-final slot. This is a CONFIRMED format source, distinct from the not-published per-block counts of §0.

## 2. Sections and timings (CONFIRMED, current composition page)

The section split, not the block counts, is what `PAPER_BLUEPRINTS` (`packages/item-engine/src/paper.ts:70`) already encodes and already gets right.

| Level | Sections (科目) | Time per section | Count |
|---|---|---|---|
| N5 | 言語知識（文字・語彙） / 言語知識（文法）・読解 / 聴解 | 20 + 40 + 30 min | 3 |
| N4 | 言語知識（文字・語彙） / 言語知識（文法）・読解 / 聴解 | 25 + 55 + 35 min | 3 |

At N2/N1 the vocabulary, grammar and reading 大問 are printed as one continuous 科目 with a single timer and 大問 numbered **continuously 1-14 (N2) / 1-13 (N1)** across all three kinds. N3/N4/N5 split 文字・語彙 off first and restart 大問 numbering per 科目.

**TASK-173.6 residual, accepted and documented rather than closed.** AC#4 refuses a 文の組み立て item when a *different* offered fragment could fill the ★ slot to rebuild a sentence the corpus actually attests. That attestation is deliberately conservative: a reassembly counts as a second answer only when it is byte-present in the corpus's own example sentences. A reassembly that is grammatical Japanese but occurs nowhere in the corpus is not counted, so such an item ships. The accepted risk is narrow: a JLPT 文の組み立て blank has one correct answer, so an unattested-but-plausible reassembly almost never has one of its fragments offered as a distractor, and the mask plus §1's rule ② already strip the mechanical second-answers (a `。`-closing fragment parked in a non-final slot). The rejected alternative, flagging two fragments as interchangeable whenever their split boundaries sit adjacent in the token stream, was dropped because adjacency is a property of the tokenizer's segmentation, not of the language: it refuses genuinely-unique items (a false ambiguous) and shrinks the fill floor for no correctness gain.

## 7. The instruction sentence each filled 大問 prints (TASK-173.2)

All ten files are the 2018 公式サンプル問題 set §1 names (`https://www.jlpt.jp/samples/sample2018/pdf/N{1..5}{V,G}.pdf`), so they are pre-reform papers and this is the newest wording available offline.

- **N2G and N1G are excerpt PDFs, not whole papers.** The 2018 set splits the merged 言語知識・読解 科目 across files, so those two files begin at 問題7 and 問題5. Their 文の文法1 sentence is therefore read from a mid-科目 page, and the 大問 heading above it is in the sibling file. The wording itself is the paper's; only the heading layout is missing.
- **`pdftotext` cannot be trusted for these strings.** §1 already notes the broken number encoding; the same layer drops the full-width blank glyphs (`＿＿＿`, `（　）`) that carry the question, so a transcription taken from text output silently loses the blank. Each page was read from a render instead: `pdftoppm -r 150 -f <page> -l <page> -png`, then look at the PNG.
- **The wording splits into three level bands, and the split is part of the transcription.** N1/N2 print kanji-dense 言葉の読み方…選びなさい and 次の文の（　）に入れるのに…選びなさい. N3 is transitional: the same sentence shape but kana for the verb (ことばの読み方…えらびなさい, つぎの文の…えらびなさい). N4/N5 print the fully spaced hiragana form (＿＿＿ の ことばは ひらがなで どう かきますか。…, （　）に 何を 入れますか。…). Copying one band's string into another level is a wording fabrication of exactly the kind §0 forbids, so the guard test rejects a Latin letter (the papers set the options １・２・３・４ in full width, never 1234) and an em dash (R-02).
- **Where the sentence lives is a deliberate deviation from AC#3.** The acceptance criterion names the ui copy deck; the strings are in the item-engine block table instead, because the deck is one key per rendered label while this is a per-(block, level) lookup over data the same module already owns (`PAPER_BLOCK_SHAPES`). The R-02 em-dash guard the AC names (`packages/ui/test/copy-snapshot.test.ts`) cannot see a table outside the deck, so the same check lives with the strings. Recorded on TASK-173.2 rather than silently diverging.
- **The other half of what a 小問 prints is per item, not per 大問, and is not in this table.** A 漢字読み 小問 prints the word in `＿＿＿`, and `items.stem` (`0016_item_stem.sql`) stores it as 「cue」; a 文の文法1 小問 prints its blanked sentence, which `passage` already carries, so it has no stem. N3V p.3 confirms the 漢字読み shape: each 小問 is a full sentence with the queried word underlined, which is why the stored stem is the word and not the sentence.
