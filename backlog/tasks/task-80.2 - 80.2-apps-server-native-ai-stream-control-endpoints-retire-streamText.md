## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Immediate rewrite of the chat surface (no dual path). Transport amendment 2026-09-16 (user decision; supersedes the earlier per-turn SSE + REST wording): oRPC v2 instead of raw Hono SSE + REST, INSPIRED by AionUi adapter semantics, not a port (upstream = plain fetch + raw WS event bus, zero oRPC). Split rule: anything participating in the live turn rides a WebSocket RPCHandler (@orpc/server/websocket, wired into the Bun.serve websocket hooks; fetch handler calls server.upgrade on the /ws path); anything reading or writing persisted state becomes a procedure on the existing fetch /rpc router. FRAME STREAM: chat.subscribe {conversationId} is an AsyncIteratorObject procedure over WS yielding AionUi IResponseMessage-shaped frames ({type, data, msg_id, turn_id, conversation_id, status?, replace?}) with the AionUi vocabulary: start, content, thinking, plan, acp_tool_call, acp_permission, ask, acp_terminal_output, acp_context_usage, available_commands, agent_status, finish, error, user_created. The server persists each frame to the messages table with a per-conversation monotonic seq and yields with withEventMeta({id: seq}); a resubscribe replays persisted frames after lastEventId then flips to live (turn survives socket drop and reload; the per-turn Bun.serve timeout-0 SSE workaround becomes unnecessary; socket close never issues session/cancel). TURN COMMANDS (WS link): chat.send {conversationId?, agent?, assistant?, model?, messages: [{role, content, files?}]} returns an ack {turn_id} (mirrors AionUi ISendMessageResult): ensures a conversation row (new conversations/messages tables in user.db via a packages/db migration), then runs prompt() through the existing per-key queueFor + ensureAcp-equivalent pool re-keyed on AcpSession (80.1); frames go to the conversation subscription, NOT the send response. chat.confirm {conversationId, callId, msgId, data, alwaysAllow?}; chat.answerAsk {conversationId, requestId, answers:[{question,labels[]}]} or {decline:true} (dedicated channel, never the confirm endpoint; AionUi 2026-08-05 ruling); chat.cancel {conversationId, turnId} issues session/cancel + releases the queue slot; chat.killTerminal {conversationId, terminalId} stops the child without cancelling the turn; chat.listConfirmations {conversationId} reads the live pending permission/ask futures from the session pool (recovery payload for pending cards on mount/resubscribe) and rides the WS link with the rest of the turn surface. FETCH-LINK PROCEDURES: chat.createConversation, chat.listMessages (cursor limit/before; _compact truncation of big tool outputs at write time), chat.slashCommands, chat.setConfigOption (model/mode switching; rpc.ts agentModels rewired to config_options). ask_user becomes a real MCP host tool served through the session's mcpServers (small in-server stdio MCP: a blocking tools/call that emits an ask frame and resolves when chat.answerAsk lands; explicit configurable host timeout + error path). Persona delivery: ACP has no session-scoped system prompt; prepend the persona text (resolvePersona unchanged) to the first prompt of a session; if an agent CLI rejects leading blocks, fall back to session/new _meta injection when advertised, else per-prompt prepend (warn + document). Contract: chat procedures + the frame discriminated-union zod schemas live in packages/api-contract so chat-session and server share one source of truth. DELETE (clean cutover, no shims): streamText/convertToModelMessages/tool/isStepCount/validateUIMessages/UIMessage imports, ASK_USER_HANDOFF sentinel + askUserTool/acpTools/chatTools, the POST /ai Hono route + AiRequestSchema/zValidator path + the V3 toUIMessageStreamResponse comment block, test/ai-hardening.test.ts; rewrite the routes.smoke /ai case against the router (call()/createRouterClient for logic, plus one live WS round trip through the Bun.serve upgrade). Existing oRPC acp.agents/assistants keep working (registry unchanged).
