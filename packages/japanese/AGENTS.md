# packages/japanese

## Purpose

- Data home + fetch scripts for the JLPT corpora: vocabulary (N5–N1), grammar points, conjugation tables, kanji, and pitch-accent. The only consumer is the Rust MCP server `crates/jlpt-mcp`, which embeds these JSON files at compile time via its `build.rs` (gzipped). The TypeScript lookup engine was ported to Rust (`crates/jlpt-mcp/src/engine.rs`) — no TS engine lives here anymore.

## Work Guidance

- The data file shapes are a **hard contract** with `crates/jlpt-mcp`: `build.rs` lists every embedded file, and `src/types.rs` deserializes them. A shape change breaks the Rust crate — update `build.rs` + `types.rs` (and regenerate the parity golden) in the same commit.
- Fetch scripts re-serialize upstream JSON to a stable shape; commit the resulting files. They are the single source of truth.
- Do not re-add a TS lookup engine here — lookup/search/conjugation logic now lives in `crates/jlpt-mcp/src/engine.rs`.
- `data/reading/` and `data/verbs-n5.json` are **shipped runtime resources**, not only corpus input for the `check-*` gates: the sidecar opens every `data/reading/{level}{suffix}.json` name its loaders derive (`apps/server/src/services/exam-corpus.ts`) while assembling a paper, so a new store filename is a bundle change too. `tauri.conf.json` `bundle.resources` carries the whole directory, and `apps/server/test/bundle-resources.test.ts` fails when a loader outruns it (TASK-178: the directory was absent from the packaged app while `n5.json` was present, and a real paper lost every 表記/読解/聴解 大問 at every level without any layer erroring).
