# packages/ui

## Purpose

- Shared shadcn/ui primitives, DS-constrained wrappers (Button, Text, Stack), hooks, lib utils, and global CSS tokens consumed by `apps/desktop`. Style preset: `base-lyra`, base color `neutral`, Tailwind v4 with CSS variables.

## Ownership

- Project contributors.

The copy snapshot test walks the whole deck. **`t()` agrees with the numbers it substitutes (TASK-163)**: a count string carries an ICU-lite clause `{total, plural, one {item} other {items}}` and `t()` resolves it through `pluralize` before the plain `{k}` pass, so the arms live in the deck and no caller can forget a var. Both arms are literal text (the count itself stays a separate `{n}`), and a missing or non-numeric var falls to `other`, which never leaks the clause into the UI. A new string that prints a count uses the clause; the six live ones are `paper.build.running`, `paper.build.ready`, `paper.build.exhausted`, `paper.offline.seed`, `exam.pause.recorded` and `review.header`. `chat.untitled` is the deck's one name for a conversation with no title, which `apps/desktop/src/lib/chat-title.ts` reads for all three chat surfaces. DrillCard renders its why-answer panel only when `resolution.explanation` is non-null (TASK-137): the exam debrief's `explanationGenerated` flag is derived from that column, so the server's stub produced a `Generated from {anchor}` heading over a placeholder on both the exam review row and a replayed drill. Gate the panel on the prose, not the flag. Drill summaries consume stored snapshot counters (`correct`, `skipped`, `unanswered`, `nextReview`) and show honest fallback text when an older row has no optional counter, never `?` or an invented FSRS interval. Paper result projections expose only submitted facts: raw counts or band/gate results, weak anchor ids, and save state. **No surface in this package prints a corpus id to a learner** (TASK-160 closed all three: `drill.explain.generated` lost its `{anchor}` parameter and is now the plain heading `Generated explanation.`, the exam review row reads `anchorLabels` from the debrief instead of `anchors`, and the chat `PaperCard` "Missed:" line reads `debrief.weakAnchorLabels` while `weakAnchors` stays only as list keys). When a frame stored before the field has ids but no names, `PaperDebrief` shows nothing rather than a join key - degrade by saying less, never by leaking the id. TASK-128's exam review keeps the generated explanation and correct option in the submitted-only debrief surface, not in the shared transcript card. `exam.review.dispute` is `Report a wrong answer`, NOT a verdict sentence (TASK-137, `doc-19` §12.2 finding 4): the control sits on every review row, including the rows the learner answered correctly, so the old wording `This answer is wrong` stated a falsehood on the ones that were right. An action label also survives the correct-row case, which is why the deck does not hide the control there; the after-state `Disputed` is rendered by the desktop pane, not the deck. The card interface must never admit answer indexes, listening scripts, explanations, FSRS links, or option-source keys.
- Apps consume via the `apps/desktop/components.json` aliases (`@/components` → app-local; `@/lib` → app-local; `@/hooks` → app-local; `ui` → `@manobu/ui/components`; `utils` → `@manobu/ui/lib/utils`).
- `Card` carries `[container-type:inline-size]` (named container `card_header`, powers the <400px CardHeader query in `globals.css`). Interface consequence (TASK-90): inline-size containment contributes 0 to a fit-content parent, so a `w-full` Card inside a `w-fit`/fit-content wrapper collapses to 0 width. Callers that place a Card in a `Bubble` (or any `w-fit` surface) must stretch the wrapper (see chat-session `STRETCHED_TYPES`), not override the containment. `DrillCard` follows the same `w-full` rule; the host transcript owns the shared `max-w-2xl` measure, so the card adds no competing max-width.
